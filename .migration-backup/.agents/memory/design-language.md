# App-wide design language

The user picked this direction from a canvas mockup (`artifacts/mockup-sandbox/src/components/mockups/TrainingLogFullVariant.tsx`) and asked for it app-wide (Aug 2026).

**The look:** near-black bg, uppercase `text-[10px] tracking-[0.18em]` micro-labels (Inter — **monospace is banned** per user, Aug 2026: `--font-mono` resolves to the sans stack on purpose, so `font-mono` classes render Inter; don't reintroduce a real mono face or re-add IBM Plex Mono to the fonts link), `TRAINING / <PAGE>` breadcrumbs, font-black tight-tracked headlines with `.text-gradient-primary` (primary→#818cf8) accent word, hairline `border-border/10..20` flat panels (not card-3d), tabular-nums figures, border-y stat strips, Apple Stocks-style charts (segmented 1W/1M/1Y/All pills, gradient-fill AreaChart, dots only when ≤35 points).

**Why:** explicit user choice via mockup iteration; consistency beats the old raised card-3d style.

**How to apply:** reference implementations are `client/src/pages/home.tsx`, `client/src/pages/stats.tsx`, `client/src/components/page-header.tsx` (all pages inherit the header). Page bodies open with a full-bleed `StatStrip` (`client/src/components/stat-strip.tsx`, the -mx border-y hairline band with gradient tabular figures) — use it, don't hand-roll new stat bands; comp/PB surfaces use `.text-gradient-gold` (amber→orange) instead of the primary gradient. The conversion is now app-wide and was done by redefining the SHARED tokens, not per page: `.card-3d` = flat hairline transparent panel, `.eyebrow` = 10px/0.18em uppercase micro-label, `.page-title` = heavy DM Sans tight-tracked (used by Dialog/AlertDialog titles — keep the class), and the shadcn primitives (dialog/popover/dropdown/select/tabs/input/button radii + hairline borders). **Bebas Neue is fully retired** — removed from the Google Fonts link, boot splash, and all `font-display` usages; big figures are `font-semibold tracking-[-0.04/-0.05em] tabular-nums`, headings `font-black tracking-[-0.04em]`. Don't reintroduce Bebas/`font-display`, and don't revert new-style surfaces back to raised cards. Floating surfaces need explicit bg now that card-3d is transparent (coach-widget uses bg-background/95). `PageHeader`'s API/exports (`headerActionClass` etc.) and collapse behavior must stay stable. Its expanded mobile headline is vw-clamped (`clamp(26px,9.7vw,38px)` + `break-words`) because iOS page-zoom/text-size boosts shrink the CSS viewport and a fixed-px headline word ("progress.") clipped at the edge on the user's phone — don't reintroduce fixed-px mobile headline sizes (home's hero already clamps its own). Readability floor (user: "fonts too dark", Aug 2026): text opacity modifiers below ~/40 were globally raised (/15→/40 … /45→/60) — don't reintroduce `text-*-foreground` below /40; page glow heroes pull up with `-mt-6 md:-mt-8` so no black band shows above them.

**Gradient-text paint box:** the `.text-gradient-*` classes carry `padding: .16em .1em .22em .04em` with mirror negative margins — `background-clip: text` only paints the line box, so the tight `leading-[0.92]` headlines had their g/p descenders (and the last glyph's ink under negative tracking) shaved to transparent on real phones (user-reported; invisible in 2x JPEG shots — verify glyph edges at dpr 3). Keep the padding/margin pair intact and use the classes instead of inline `WebkitBackgroundClip` styles.

**Per-page accent identity (Aug 2026, user: "use the pages icon's colour"):** every page scopes `--page-accent`/`--page-accent-2` (HSL triplets) to its nav-icon color — map in `client/src/lib/page-accent.ts`, applied via `<PageLayout accent="…">` (skills.tsx applies `pageAccentStyle("skills")` on its own root div because it isn't on PageLayout). Section surfaces inherit identity through `.text-gradient-page`, `hsl(var(--page-accent)/x)` tints, and `StatStrip accent="page"` (strip-level default prop); PageHeader's glow/kicker/accent word follow automatically. Home stays default blue — it's the user's beloved reference; don't retint it. Severity colors (rose deduction indicators, amber/red chart bars) are semantic, not identity — don't convert them to the page accent.

**Back-navigation scheme (Aug 2026, user: "lets have a scheme for the entire app"):** every subpage (detail/tracker/debuts pages) opens with the shared `<BackLink>` (`client/src/components/back-link.tsx`) as the FIRST content element — quiet 11px mono-caps "← Parent Name", muted at rest, hover tints to `--page-accent`. Don't hand-roll per-page back buttons, don't put back-nav in PageHeader `actions` (user rejected both a floating pill above the header and the header-action placement), and note BackLink is inline-flex — give it its own line (wrapper div) when a sibling inline element follows. On pages with a PageHeader, pass it via the header's `backLink` prop (renders inside the glow, collapses away on scroll) instead of placing it above the header.

**No black strip above heroes (Aug 2026, user: "whats the top black? delete from everywhere"):** PageLayout's `py-6 md:py-8` top padding shows plain bg above any hero that doesn't pull up — every full-bleed glow hero must carry `-mt-6 md:-mt-8` on the bleed wrapper and move the breathing room INSIDE (`pt-6 md:pt-8` on the inner relative div) so the gap is tinted by the glow, not black. Sticky PageHeader pages already cover it via `page-header-safe`. `pt-safe-top` is a DEAD class (only `.pt-safe` exists; the App shell already applies it globally) — don't copy it into new heroes.

## Points to Fix dialog identity
Amber is the Points-to-Fix identity everywhere (wrench, glows, CTAs): dialog gets the page-hero treatment scaled down — amber radial glow w/ bottom mask at top of DialogContent, mono-caps amber eyebrow ("Training focus"), "Points to fix." headline, mono-caps count strip. Rows are hairline-divided (divide-y) with a 4px amber dot per active point, not bg pills. Amber CTAs need `border-amber-600/60` or the Button default variant's blue `border-primary-border` shows through. The unlinked card suppresses its "General" category label (card is already titled General). Add dialog lives at fragment level so the empty state's CTA can open it.

## Popup hero headers
Every form popup uses the shared `DialogHero` component (client/src/components/dialog-hero.tsx): page-accent glow, mono-caps eyebrow + page icon, 22px bold title with accent period (`noPeriod` for questions/step counters), optional description and right-aligned action. Dialogs are portaled, so DialogContent must scope the accent itself via `style={pageAccentStyle("<page>")}` — omit for primary-blue contexts (note-dialog subs). Don't hand-roll new dialog headers; extend DialogHero.
